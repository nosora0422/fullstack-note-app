# AGENT.md

This file gives future Codex sessions quick context for working on this project.

## Project

React Note App is a Create React App project for notes, image notes, and to-do lists.

Core stack:
- React 18
- React Router
- Tailwind CSS
- Firebase Authentication
- Cloud Firestore for signed-in user app data
- localStorage for guest app data

Run locally:

```powershell
npm install
npm start
```

Build check:

```powershell
npm run build
```

## Routing

The app uses `HashRouter` in `src/index.js`.

Current route map:
- `/login`
- `/signup`
- `/guest/todos`
- `/guest/notes`
- `/guest/images`
- `/app/todos`
- `/app/notes`
- `/app/images`
- `/settings`

Legacy app routes redirect:
- `/app/to-do-list` -> `/app/todos`
- `/app/note` -> `/app/notes`
- `/app/image` -> `/app/images`

Authenticated app routes are protected by `src/routes/ProtectedRoute.js`.
Guest routes are initialized by `src/routes/GuestRoute.js`.

## Authentication

Firebase Auth is configured in `src/firebase.config.js`.

Supported sign-in methods:
- Email/password
- Google popup login

Login component:
- `src/Login/Login.js`

Signup component:
- `src/Signup/Signup.js`

Validation:
- `src/LoginValidation.js`
- `src/SignupValidation.js`
- Firebase error message mapping lives in `src/utils/authErrors.js`

When auth succeeds, app mode is set to `user` and the user is sent to `/app/todos`.

## Storage Model

Signed-in user data is saved in Cloud Firestore. Guest data is saved in browser localStorage only.

Firebase app, Auth, and Firestore are configured in:
- `src/firebase.config.js`

Firestore helpers live in:
- `src/services/firestoreService.js`

Firestore document shape:
- `users/{uid}/notes/{noteId}`
- `users/{uid}/todos/{todoId}`
- `users/{uid}/images/{imageId}`

Firestore helper functions:
- `getUserItems(uid, dataType)`
- `addUserItem(uid, dataType, item)`
- `updateUserItem(uid, dataType, item)`
- `deleteUserItem(uid, dataType, itemId)`
- `deleteUserItems(uid, dataType)`
- `deleteAllUserItems(uid, dataTypes)`

The list components pass object keys directly to Firestore. Firestore is schema-less, so saved document fields come from each item object:
- Notes: `id`, `title`, `note`, `category`, `date`
- Todos: `id`, `title`, `tasks`, `category`, `date`
- Images: `id`, `title`, `path`, `note`, `category`, `date`

Storage helpers live in:
- `src/utils/storage.js`

Session mode key:
- `note_app_mode`

Guest localStorage keys:
- `note_app_guest_notes`
- `note_app_guest_todos`
- `note_app_guest_images`

Signed-in users should not write notes/todos/images to localStorage. Use Firebase `uid` with the Firestore `users/{uid}` path, not email.

Legacy keys may exist from the older version:
- `note_data`
- `todolist_data`
- `image_data`

Current list components call `migrateLegacyData()` only for guest mode so old data can move into the active guest storage key.

Current list components:
- load from localStorage when `mode === "guest"`
- load from Firestore when `mode === "user"`
- write to localStorage only when `mode === "guest"`
- create/update/delete Firestore documents when `mode === "user"`
- show loading and error messages during data loading

## Guest Behavior

Guest users can create notes, todos, and image notes with localStorage.

Guest data should be temporary:
- Guest logout clears all guest localStorage data.
- Guest browser/tab exit uses `beforeunload` in `src/App.js` to clear guest data.

Be careful: `beforeunload` can also run on refresh, so guest data may clear when refreshing the page.

## Settings

Settings page:
- `src/Settings/Settings.js`

It allows the active guest/user session to clear:
- Notes
- To-do lists
- Images
- All saved data

For guests, Settings clears localStorage keys.

For signed-in users, Settings deletes Firestore documents using `deleteUserItems()` and `deleteAllUserItems()`.

It also includes logout behavior.

## Important Notes For Future Updates

- Do not mix guest and signed-in user localStorage keys.
- Keep `/guest/...` and `/app/...` navigation separate in `src/shared/Header/Header.jsx`.
- Signed-in user notes/todos/images now sync through Firestore.
- Keep Firestore security rules user-scoped: users should only read/write `users/{uid}` where `request.auth.uid == uid`.
- Firebase frontend config can be committed, but service account keys and real secrets must never be committed.
- `build/` is generated output. Do not edit it manually.
- `src/dist/output.css` is generated by Tailwind. Prefer editing source classes and regenerating CSS through the existing npm scripts.
